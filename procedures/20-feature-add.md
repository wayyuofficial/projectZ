# 절차 20 — 게임에 뭔가 추가·수정하기

## 이름과 용도
유닛·웨이브·UI·밸런스 등 게임 내용을 하나 바꿀 때 부른다. **한 번에 하나만 바꾼다.**

## 읽을 것 (순서대로, 이것만)
1. `canon/10-scope.md` — 상한 (유닛 6 / 웨이브 10 / 별 3)
2. `canon/30-forbidden.md` — 금지 목록
3. `game/*.html` — 바꿀 부분만
4. (해당될 때만) `rules/` 중 이번 작업과 관련된 규칙 본문

규칙 내용을 여기에 베껴 쓰지 않는다. 규칙 파일을 가리킨다.

## 만들 것
- `game/*.html` 수정 (단일 파일 유지)
- 사람에게 보고 1줄: 무엇을 바꿨고, 검사 결과가 무엇인지

## 절차
1. 바꿀 것을 한 문장으로 적는다. 두 문장이 되면 작업을 쪼갠다
2. `canon/10-scope.md` 상한에 걸리는 변경인지 본다.
   → 상한을 넘어야 하는 일이면 **여기서 멈춘다.** 절차 10으로 가서 지시를 받는다
3. 데이터 테이블(`UNIT_TYPES` 등)에서 고칠 수 있으면 로직을 건드리지 않는다
4. 수정한다. → **검사**: `python checks/run.py` 종료 코드 0
5. 브라우저에서 직접 열어 1런을 돌려본다. → **검사**: 콘솔 오류 0건
   - **화면 상태가 여럿이면 상태마다 한 번씩 그려본다.** 기본 화면만 보는 것으로는 부족하다.
     현재 상태: 평소 · 사망 · 오프라인 팝업 · 저장 실패
     (2026-09-08: 팝업을 한 번도 안 띄워봐서 닫기 버튼이 덮인 것을 못 잡았다 — 사례 09)
6. 사람에게 보여주고 승인을 받는다 (확인 주기 = 매 작업마다)
- 재시도 상한: 2회. 2회 안에 검사를 못 통과하면 되돌리고 사람에게 보고한다

## 하지 않는 것
- 여러 기능을 한 번에 넣지 않는다
- `canon/10-scope.md` 의 상한을 고치지 않는다
- 게임을 여러 파일로 쪼개지 않는다
- 서버 통신을 넣지 않는다
- 검사를 건너뛰고 "될 것 같다"로 넘어가지 않는다
