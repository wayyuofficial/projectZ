# 절차 40 — 사례를 규칙으로 승격하기

## 이름과 용도
같은 패턴 이름을 가진 사례가 **2개** 쌓였을 때 부른다. 1개면 아직 아니다.

## 읽을 것 (순서대로, 이것만)
1. `cases/` 파일 목록 — 패턴 이름별 개수 세기
2. 해당 패턴 사례 2개의 본문
3. `rules/` 목록 — 같은 대상을 다루는 규칙이 이미 있는지

## 만들 것
`rules/R###-패턴이름.md` 1개. 머리 4줄은 강제다:

```
근거: cases/... , cases/...   (2개 링크)
충돌검토: 부딪히는 규칙 번호와 처리. 없으면 "없음"
대상: 한 단어
유효기한: YYYY-MM-DD 또는 "없음"
```

## 절차
1. 패턴 개수를 센다 — `ls cases/ | grep 패턴이름`
   → 2개 미만이면 **여기서 끝낸다.** 승격하지 않는다
2. 규칙 문장을 한 줄로 쓴다. 두 줄이 되면 패턴이 둘로 섞인 것이다. 나눈다
3. 머리 4줄을 채운다. 근거에 사례 2개를 반드시 링크한다
4. **셀 수 있는 규칙인지 본다.**
   - 셀 수 있다 → `checks/` 에 검사를 추가한다. 근거가 사례면 `PRIORITY = 1`, 가설이면 `2`
   - 셀 수 없다 → 해당 절차서에 단계로 박는다. 규칙 파일에 "왜 검사로 못 내리는가"를 적는다
5. **검사**: `python checks/run.py` → C1(규칙 위생) 통과 확인
6. 검사를 추가했으면 **검사**: `python tools/selftest_checks.py` → 새 검사가 위반을 실제로 잡는지 확인
- 재시도 상한: 2회

## 하지 않는 것
- 1회짜리 사례를 규칙으로 올리지 않는다
- 근거 없는 규칙을 만들지 않는다 (C1 이 막는다)
- 같은 대상을 다루는 규칙을 둘로 만들지 않는다 (C1 이 막는다)
- 규칙 본문을 절차서에 베껴 쓰지 않는다. 가리킨다
