# 사례 — 목록 줄만 재고 "탭 대상 전부" 라고 했다

패턴 이름: **대표성없는표본**
날짜: 2026-09-10
근거: `measurements/verify/verify-2026-09-10-16.json` (16차 빠른 감사) / instructions-log.md 지시 #55

## 상황
같은 날 15차 감사가 [[2026-09-10-13-대표성없는표본]] 을 잡았다 — 스크롤이 없는 한 조합에서 재고 전 범위라 했다.
그래서 **범위를 훑는 스윕**을 만들었다: 폭 280~540 × 화면비 73단 × 탭 2 × 스크롤 10자리, **414,142개**.
눌리는 줄 최소 **29.000 CSS px**, 29 미만 0. `measurements/tap-2026-09-10.json` 에 적고 커밋했다.

## 판단
"이번엔 범위를 훑었으니 됐다" 고 봤다. 판정 문구는 **"모든 탭 대상 높이 ≥ 29 CSS px"** 다.

## 결과
**스윕이 센 것은 목록 줄뿐이었다.** 파일 안 표본 이름부터 `목록줄_표본` 이다.
목록 밖의 고정 높이 버튼 3개 — 부활 제안(46) · 오프라인 '닫기'(46) · '광고 보고 2배 받기'(52) — 는
414,142개 안에 **하나도 없었다.**

16차 감사가 실뷰포트 320x568(iPhone SE)에서 부활 버튼 **27.259 CSS px** 를 재고 실제로 눌러
구역 5→7 복귀가 일어나는 것을 확인했다. 280x530 은 23.852. h=46 은 폭 340 미만에서, h=52 는 301 미만에서 미달이다.

**15차가 잡은 것을 고치면서 15차가 잡은 것과 같은 일을 했다** — 표본이 대상을 대표하지 않았다.
13 은 *조합* 하나만 봤고, 14 는 *종류* 하나만 봤다. 축이 다를 뿐 같은 실수다.

## 교훈
1. **판정 문구의 주어를 표본 이름과 대조한다.** 문구는 "모든 탭 대상", 표본은 "목록 줄". 이름이 다르면 표본이 모자란 것이다.
2. **범위를 넓힐 때는 축을 전부 센다.** 13 에서 조합 축을 넓혔고 종류 축은 그대로 하나였다.
   "훑었다" 는 한 축에서만 참일 수 있다.
3. **잰 뒤에 "이 판정 문구에 속하는데 내 표본에 없는 것이 무엇인가" 를 한 번 묻는다.**
   `buildButtons()` 가 만드는 `kind` 를 나열해 보기만 했어도 셋이 빠진 것이 보였다.
4. 같은 패턴 **2회** → 규칙으로 올린다: `rules/R004-대표성없는표본.md`

- 세 버튼 h → `ROW_H`(58). 부활 y `ARENA_BOT-70`, 닫기 y `GAME_H/2+108`. 탭 대상은 이제 전부 58 이다.
- 스윕을 **모든 버튼**으로: 692,710 표본, 눌리는 것 최소 29.000, 종류별 최소 30.074. `measurements/tap-2026-09-10b.json`
- 포트 `hitButton` 의 `css_per` 이 `fit_game` 전 0 이 되어 판정선이 꺼지던 구멍(16차 부수 지적)도 막았다.
