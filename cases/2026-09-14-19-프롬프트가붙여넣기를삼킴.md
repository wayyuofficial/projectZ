# 사례 — 이름 프롬프트가 다음 명령줄을 삼켰다

패턴 이름: **프롬프트삼킴**
날짜: 2026-09-11 (발견 2026-09-14)
근거: `plans/predictions-lock.json` M2-B4 판정이력 2번째 항목 / instructions-log.md 지시 #73·#74

## 상황
25차 감사 뒤 사람이 실행할 명령 두 줄을 한 번에 드렸다.

```
python tools/judge_prediction.py M2-B4 ...        ← 실행하면 이름을 묻는다
python tools/judge_prediction.py M2-B1‴ ...       ← 이 줄이 이름 칸으로 들어갔다
```

## 결과
- **M2-B4** 는 반증으로 바뀌었지만 `판정한_사람` 이 `python tools/judge_prediction.py M2-B1‴ ...` 로 남았다.
  `plans/GAMEDESIGN.md` 예측표 칸에도 그대로 찍혔다 — **문서가 판정자를 잘못 적고 있다.**
- **M2-B1‴** 은 판정이 아예 안 됐다. 그 줄이 입력으로 먹혔으니까.
- 사흘 뒤 사람이 그 명령을 다시 실행하니 `이미 그 판정이다` 로 멈췄다 — **근거만 갱신할 길이 없었다.**

## 판단
도구 문서에 "여러 명령을 한 번에 붙여 넣으면 프롬프트가 다음 줄을 삼킨다 — 한 줄씩 실행한다" 고
**주석으로만** 적혀 있었다(57행). 사람이 읽는 곳이 아니다. 글로 적고 막지는 않았다.
그리고 내가 답변에 두 명령을 나란히 놓아 붙여 넣기 쉽게 만들었다.

## 교훈
1. **사람이 값을 치는 프롬프트는 명령줄처럼 생긴 입력을 거부해야 한다.** 주석은 막지 못한다.
2. 사람에게 명령을 드릴 때, **프롬프트가 뒤따르는 명령은 한 번에 하나만** 드린다.
3. 판정 도구가 "판정은 그대로, 근거만 갱신" 을 못 했다 — R005/c19 를 켜 놓고 끄는 길이 없었다. 설계 구멍.

## 고친 것
- `tools/judge_prediction.py`
  - 이름 칸이 `python`으로 시작하거나 `judge_prediction`·`--` 를 담거나 30자를 넘으면 **거부하고 아무것도 안 바꾼다.**
  - `--근거만` 신설 — 판정은 그대로 두고 근거만 다시 남긴다(`--why` 필수, 판정이 다르면 거부). 이력에 `종류: 근거재기록`.
- `checks/c19_evidence_stamp.py` — **마지막** 판정 이력만 본다. 지난 이력의 옛 기록까지 잡아 거짓 경고를 냈다.
- 시험: 새 경로 5가지를 잠금 **복사본**에 대고 돌렸다(거부 3종 + 정상 2종). 저장소 기록은 안 건드렸다.

## 남은 것 (사람 몫)
- M2-B4 의 잘못 박힌 판정자 이름은 `--근거만` 을 사람이 한 번 실행하면 문서 칸이 바로잡힌다.
  **판정이력의 잘못된 항목은 지우지 않는다** — 무슨 일이 있었는지가 이력이다.
