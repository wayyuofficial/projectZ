# 사례 — 캔버스 글자가 깨져 보임

패턴 이름: **백버퍼정합**
날짜: 2026-09-08
근거: instructions-log.md 지시 #12

## 상황
WBS 1.1 골격을 만들고 검사 9개를 모두 통과시킨 뒤 "완료"로 보고했다.
사람이 화면을 보고 "폰트 해상도가 많이 떨어지네"라고 지적했다.

## 판단
캔버스 백버퍼를 **논리 해상도 기준**으로 잡았다 — `canvas.width = GAME_W * dpr = 540 × 2 = 1080`.
그리고 픽셀아트를 아직 넣지도 않았는데 `image-rendering: pixelated` 를 미리 켜 두었다.

## 결과
실제 표시 크기는 CSS 981px = 물리 1962px 이었다. 1080을 1962로 **1.817배 늘려** 그리고 있었고,
`pixelated` 때문에 최근접 이웃 보간이 적용돼 글자 획이 계단으로 부서졌다.

2차 실수도 있었다. 고치면서 백버퍼 상한을 `MAX_BACK_W = 1620` 으로 걸었는데 이 화면에는 1962가 필요해
**342px 어긋난 채로** 여전히 늘어났다. 상한을 2160으로 올려서야 `1:1` 이 됐다.

수정 후 실측: 백버퍼 1962 × 3488, 적용 DPR 2.00, 픽셀 정합 **1:1**.

## 교훈
1. 캔버스 백버퍼는 논리 해상도가 아니라 **실제로 표시되는 물리 픽셀 수**(CSS 크기 × devicePixelRatio)로 잡는다.
2. 픽셀아트가 없는데 `image-rendering: pixelated` 를 켜지 않는다. 넣을 때 그 스프라이트에만 국소로 건다.
3. 성능 상한을 걸었으면 **그 상한에 걸렸는지를 화면에 표시**한다. 안 보이면 조용히 흐려진다.
4. **가장 중요한 것** — 1.1의 완료 판정에 "잘림·여백"만 있고 **화질이 없었다.**
   검사 9개를 다 통과했는데도 사람 눈에는 명백히 잘못돼 있었다.
   판정 항목에 없는 것은 검사도 못 잡는다. WBS 1.1 완료 판정에 화질 항목을 추가했다.

## 검사로 내릴 수 있는가
일부는 가능하다. 아직 **1회 관측**이라 규칙으로 승격하지 않는다(승격 조건 2회).
같은 패턴이 한 번 더 나오면 아래를 검사로 만든다.
- 후보 C9: 게임 HTML에서 `canvas.width` 를 논리 해상도 상수로 대입하면 걸린다
- 후보 C10: 캔버스 요소에 `image-rendering: pixelated` 가 전역으로 걸려 있으면 걸린다
