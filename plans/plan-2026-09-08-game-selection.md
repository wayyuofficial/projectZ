# 계획 — 만들 게임 1개 확정하기

작성일: 2026-09-08
근거: instructions-log.md 지시 #2~#5 / 관측 #1, #2
상태: **1장 종료 조건 3개 중 3개 충족 → 계획 종료 직전. 사람 승인 대기.**

## 개정 이력
- 1판 — 최초 작성. 수익 경로 미정.
- 2판 — 지시 #4 반영. 충돌(B vs 1~2주) 기록. 예측 P2 반증 → 선정 기준 S1~S7 추가.
- **4판 — 지시 #6 반영. 질문 5·6 = "없음"(사람 진술). 과거 재고가 없으므로 사례는 이 프로젝트에서 앞으로 발생하는 것으로만 쌓는다.**
- 3판 — 지시 #5 반영. 게임 = C 소형 오토배틀러 확정. M1/M2 분리 확정. 예측 P5 성립. 코어 루프·광고 지점 기재.

## 1. 종료 조건 판정

| # | 조건 | 상태 |
|---|---|---|
| 1 | 게임 1개의 이름과 한 문장 정의 | ✅ 아래 4장 |
| 2 | 코어 루프 1장 | ✅ 아래 5장 |
| 3 | 광고 삽입 지점 3개 + 지표 조회 방법 | ⚠ **절반** — 지점 3개는 정했으나 **조회 방법 미조회(error)** |

3번이 완전히 차기 전에는 계획을 닫지 않는다.

## 2. 확정된 것

| 항목 | 값 | 근거 |
|---|---|---|
| 목적 | 수익화 — 광고·인앱 | 지시 #3 |
| 핵심 재미 | 전략·배치 + 성장·숫자 | 지시 #3 |
| 수익 경로 | B. 모바일 앱 | 지시 #4 |
| 게임 | **C. 소형 오토배틀러** | 지시 #5 |
| M1 | 내 폰에서 도는 플레이 가능 빌드 / 1~2주 | 지시 #5 (확정) |
| M2 | 스토어 등록·출시 / 기한 미정 | 지시 #5 (확정) |
| 확인 주기 | 매 작업마다. **자동 실행 켜지 않음** | 지시 #4 |
| 과거 반복 실수 | **없음** (사람 진술, 잠정) | 지시 #6. **실측 아님** — 검증되지 않은 진술 |
| 금지 사항 | **없음** (사람 진술, 잠정) | 지시 #6. 〃 |
| 구글 플레이 계정 | **있음** (사람 진술, 미검증) | 지시 #5 응답 |
| 애플 계정 | **모름** | 미답 |

## 3. 형식 — 이제 1개로 좁혀졌다

C + M1(1~2주 폰 빌드) + S4(서버 불필요) 조합에서 성립하는 형식은 하나뿐이다.

**결정(제안): 단일 HTML 캔버스 → M2에서 WebView 래핑.**

| 근거 | 종류 |
|---|---|
| 이 세션 게임 스킬 대부분이 단일 HTML 캔버스를 전제 | **사실** |
| Unity는 1~2주 안에 학습+빌드+기기 대응까지 어렵다 | **추정** (실측 없음) |
| 단일 HTML은 빌드 단계가 없어 반복 확인이 빠르다 | **사실** |

⚠ 이 결정은 사람 승인 전이다.

## 4. 게임 정의

- **가칭**: `오토배틀러 (이름 미정)`
- **한 문장**: 세로 격자에 유닛을 놓고, 자동으로 싸우는 걸 지켜보며, 웨이브마다 유닛을 합치고 강화해 얼마나 멀리 가는지 겨루는 게임.

## 5. 코어 루프 (한 바퀴 30초)

```
배치 (10초)  →  자동 전투 (15초)  →  보상 선택 (5초)  →  반복
```
- 웨이브 10개 = 1런 ≈ 2~3분 (S2 충족)
- **전략·배치**: 3×4 격자에 유닛을 어디 놓느냐로 결과가 갈린다
- **성장·숫자**: 같은 유닛 3개 = 별 등급 상승. 웨이브 보상 골드로 상점에서 뽑기·리롤

## 6. 스코프 컷 — 이걸 지켜야만 M1이 성립한다

지시 #5의 충돌(C는 유닛 종류가 많아야 성립 vs 1~2주)에 대한 처리다.

| 항목 | 상한 | 넘기면 |
|---|---|---|
| 유닛 종류 | **6종** | M1 실패로 판정 |
| 별 등급 | 3단계 (색만 바꿈 — recolor 활용) | 〃 |
| 웨이브 | **10개** | 〃 |
| 적 스프라이트 | 유닛 스프라이트 재사용 | 〃 |
| 서버 | 없음. localStorage만 | 〃 |

## 7. 광고 삽입 지점 3개

| # | 지점 | 보상 |
|---|---|---|
| 1 | 런 종료 직후 | 부활 1회 |
| 2 | 상점 | 무료 리롤 1회 |
| 3 | 런 종료 정산 | 보상 2배 |

⚠ **지표 조회 방법은 미조회(error).** 어떤 광고 SDK를 쓰고 노출 수를 어디서 읽는지 정해지지 않았다.

## 8. 미확인 사실 (error — 조회하지 않음)

- 구글 플레이 / 애플 개발자 계정 보유 여부
- 개발자 계정 등록비 실액 · 스토어 심사 소요일
- 광고 SDK 선택과 지표 조회 방법
- WebView 래핑 도구(Capacitor 등)의 실제 절차·제약
- 위 3장·6장의 "가능/불가" 판단 근거 수치

→ 원칙 9에 따라 **한 번만 조사해 실측 파일 1장으로 남긴다.** 아직 조사하지 않았다.

## 9. 예측과 반증 조건 (3판)

| # | 예측 | 반증 조건 | 판정 |
|---|---|---|---|
| P1 | 수익 경로가 형식을 결정한다 | 경로 확정 후에도 형식 미확정이면 실패 | 약한 반증 → **3장에서 회복**(게임까지 정해지자 1개로 좁혀짐) |
| P2 | 게임 확정까지 대화 2회 이내 | 3회 초과 시 실패 | **반증됨** (4회차) |
| P3 | 진짜 병목은 유통 | 출시 30일 순 설치 100 미만 | 미판정 (M2 이후) |
| P4 | 웹 래핑으로 M1 도달 가능 | 코어 루프에 서버·멀티플레이 필수 요소가 들어가면 실패 | **성립** — 5장 루프에 서버 요소 없음 |
| P5 | 기준을 적용하면 다음 1회에 게임 확정 | 확정 안 되면 기준이 후보를 못 가름 | **성립** |
| **P6** | 6장 스코프 컷을 지키면 14일 내 M1 도달 | 유닛이 6종을 넘거나, 14일차에 폰에서 안 돌면 실패 | 미판정 |

P3의 "100"은 **임의 값**이다. 실측 근거 없음.

## 10. 다음 행동 (하나만)

**8장 미확인 사실 5개를 한 번에 조사해 실측 파일 1장으로 남긴다.** 이게 끝나야 종료 조건 3번이 채워지고, 2단계 설계안을 숫자로 쓸 수 있다.

## 11. 하지 않는 것

- 실측 없이 수익·기간·비용 숫자를 단정하지 않는다
- 폴더 6종·검사 스크립트·절차서를 지금 만들지 않는다 (2단계 설계 승인 전)
- 코드를 한 줄도 쓰지 않는다
- 자동 실행을 켜지 않는다
- 6장 상한을 조용히 늘리지 않는다. 늘리려면 지시 로그에 새 항목으로 남긴다
