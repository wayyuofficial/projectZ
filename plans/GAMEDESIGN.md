## 1. 코어 루프 한 문장

> 자동으로 싸우는 생존자를 지켜보며 → 좀비를 처치해 **부품**과 경험치를 벌고 → **무기와 능력치를 업그레이드**해 강해져서 → 더 깊은 구역의 더 센 좀비를 상대한다.

이 문장에서 벗어나는 기능은 CORE 가 아니다. 5장 스코프 컷에서 잘라낸다.

### 해소된 미결 — 전략·배치는 포기했다 (지시 #9)
지시 #3에서 고른 핵심 재미는 **전략·배치 + 성장·숫자** 둘 다였다. 지시 #9로 **전략·배치를 포기**했다.
남는 재미는 **성장·숫자 하나**다. 선정 기준 S7도 함께 폐기됐다.

초안에 있던 **로드아웃 4칸**(무기1+방어구1+특성2) 제안도 **뺐다.** "조합"이든 "배치"든 새 시스템이라 스코프만 늘린다.
무기 선택(F3)은 그대로 남는다 — 그건 성장 시스템의 일부이지 배치가 아니다.

## 2. 기능 명세

### F1. 자동 전투 — CORE
- 목적: 코어 루프의 "지켜보며"
- 플레이어 입력: **없음** (방치형의 핵심)
- 즉시 피드백: 좀비 피격 플래시 · 데미지 숫자 팝업 · 처치 시 부품 아이콘이 튀어나옴
- 비용/보상: 비용 없음 / 처치당 부품 + 경험치
- 데이터: `ZONES[]` 의 좀비 HP·DPS·보상
- 상한: 화면 동시 좀비 **8마리**. 초과 스폰은 대기열

### F2. 능력치 업그레이드 — CORE
- 목적: "강해져서". 방치형의 주된 손맛
- 플레이어 입력: 버튼 탭 (길게 누르면 연속 구매)
- 즉시 피드백: 수치가 즉시 오르고 DPS 표시가 갱신
- 비용/보상: 부품 소모 / 영구 상승
- 데이터: `STATS[]` **4종** — 공격력 · 공격속도 · 최대체력 · 체력회복
- 비용식: `cost(L) = cost0 * costG^L` — costG 는 3장 실측 보정값 (atk 1.322 / spd 1.344 / hp 1.310 / reg 1.333)
- 상한: 레벨 무제한. 대신 비용 지수가 벽 역할

### F3. 무기 업그레이드 — CORE
- 목적: 성장에 "선택"을 넣는다
- 플레이어 입력: 무기 선택 + 강화 탭
- 즉시 피드백: 무기 스프라이트 색이 등급에 따라 바뀜
- 비용/보상: 부품 소모 / 무기별 고유 효과 강화
- 데이터: `WEAPON_TYPES[]` **6종** × 등급 **3단계**
  - 등급은 **색만 바꾼다** (recolor). 스프라이트를 3배로 그리지 않는다
  - 6종 예: 파이프 / 소총 / 산탄총 / 화염방사기 / 석궁 / 지뢰
- 상한: 6종 · 3등급 (정본 상한)

### F4. 구역 진행 — CORE
- 목적: "더 깊은 구역으로"
- 플레이어 입력: 다음 구역 버튼 (조건 충족 시 활성)
- 즉시 피드백: 배경이 바뀌고 좀비 종류가 바뀜
- 비용/보상: 없음 / 보상 배율 상승
- 데이터: `ZONE_COUNT = 10`, 5구역마다 보스
- 상한: 10구역 (정본 상한)

### F5. 오프라인 보상 — CORE
- 목적: **방치형이 방치형인 이유.** 다시 열게 만드는 장치
- 플레이어 입력: 앱 재실행
- 즉시 피드백: 복귀 팝업 — "자리를 비운 4시간 12분 동안 부품 8,400개를 모았습니다"
- 비용/보상: 없음 / 오프라인 DPS × 시간 × 0.5 배율
- 데이터: `OFFLINE_MAX_HOURS = 8`
- 상한: 8시간. 그 이상은 안 쌓인다 → 하루 두 번 열 이유가 생김

### F6. 광고 자리 (M1에서는 **스텁**) — CORE
- 목적: 수익 경로. **M1에서는 SDK를 붙이지 않는다.** 버튼과 자리만 만든다
- 3지점: ① 오프라인 보상 2배 ② 사망 시 부활 1회 ③ 부품 획득 2배 (10분)
- 상한: 스텁은 즉시 보상을 준다. 실제 SDK 연결은 **M2**

### F7. 저장 — CORE
- 목적: 방치형은 저장이 깨지면 게임이 끝난다
- 데이터: `localStorage` + `SAVE_VERSION` 상수 (검사 C5 대상)
- 자동 저장: 30초마다 + 구역 이동 시 + 페이지 숨김 시

### M2 — 목표 체류 곡선 (2026-09-11, 지시 #59·#60)

구역을 늘리며 상수를 만지는 대신 **"구역 z 에서 얼마나 머무는가"** 를 정본으로 둔다:

**체류(z) = 4분 × 1.05^z. 5의 배수 구역은 벽 ×3 — 그 지점이 광고 지점이다** (정본 38행을 이 곡선으로 복원).

**2026-09-11 지시 #63 (사람 결정)**: 곡선은 **구역 10~30 에만** 적용한다 — 1~9 는 M1 실측(구역당 2~4분, 사람이 "이건 게임이다" 라 한 속도)을 그대로 둔다. 벽은 **구역 10 부터** 5의 배수 구역에 **처치 수 ×2 + 처치당 보상 ÷2** (×3/÷3 은 체감 5배였다). 목표 곡선의 벽 배수도 ×2 로 읽는다.

2026-09-11 첫 측정(20시드): 구역별 체류는 무기를 사는 순간마다 **톱니**라 ±30% 기준(M2-B1)은 17개가 밖이었고, **HP ×3 벽**(M2-B2)은 이웃의 8~15배에 벽 다음 구역이 0.2분인 골짜기를 만들었다 (`measurements/balance-M2-curve-nowall-2026-09-11.json`, `-wall-`). 판정은 사람 몫. 교체 예측 **M2-B1′**(도달 시각 기준 ±20%)·**M2-B2′**(벽 = 처치 수 ×3)를 결과를 보기 전에 잠갔다. 이어서 B2′ 도 골짜기(벽 다음 구역 0.11~0.68)를 남겨 **M2-B2″**(처치 수 ×3 + 보상 ÷3 — 벽의 총수입은 보통 구역과 같다)를 잠갔다.

근거: 지금 공식은 구역당 비용 성장 ×2.94 vs 보상 성장 ×1.30 (비 2.26). 포트로 구역 30 까지 돌리면 체류가 4분 → 15~36분으로 완만히 느려지고 무기(최대 ×9, 유한)는 15구역쯤부터 죽는다 — `measurements/balance-extend-2026-09-11.json`. 격자 탐색(`balance-fit-2026-09-11.json`)에서 **HP ×1.55 유지 · 보상 ×1.35** 가 곡선에 가장 가깝다.
