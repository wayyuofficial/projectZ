## A. 플레이 경험

### A1. 소리가 하나도 없다
- **근거**: `AudioContext`·`Audio`·진동(`vibrate`) 0곳. 총소리·처치·보스·뽑기·레벨업 전부 무음.
- **느낌**: 타격감의 절반이 비어 있다. 그림(M9)·연출(M13)을 올린 만큼 소리 없는 것이 더 크게 느껴진다.
- **제안**: WebAudio 로 **합성음**(파일 없이 코드로 — 단일 파일·용량 유지): 발사(무기 종류별 3~4가지)·처치·보스 등장·뽑기 등급별·레벨업. 끄기 버튼. 진동은 보스 처치·높은 등급 뽑기만.

### A2. 스킬북이 한 판 만에 쓸 곳이 없어진다
- **근거**: 한 판 끝(구역 60)에 낀 스킬 평균 레벨 **9.1 / 상한 10**. 회차를 돌수록 스킬북이 쌓이기만 한다(환생해도 스킬 레벨이 남는다).
- **느낌**: 두 번째 회차부터 스킬 탭이 '할 것 없음'. M14 에서 스킬북을 늘린 것(A3)이 반대쪽 끝으로 넘어갔다.
- **제안**: 회차마다 스킬 상한 +2(회차 1 = 10, 2 = 12 …) 또는 남는 스킬북을 '스킬 각성'(쿨타임 −) 같은 두 번째 축으로. 거울로 스킬 몫 35% 이하를 지킨다.

### A3. 끝 콘텐츠가 '같은 60구역 × 더 센 좀비' 뿐
- **근거**: 회차 = 좀비 ×100·보상 ×4 반복. 칭호는 회차 20 에서 끝. 새 지역·새 적·새 목표 없음.
- **느낌**: 회차 3~5 쯤에서 "또 같은 길" — 방치형 장기 이탈 지점.
- **제안(택)**: ① 회차마다 **변이 규칙** 하나(예: 좀비 빠름 · 보스 둘 · 회복 없음 — 보상 +) ② 회차 10 부터 **도전 구역**(주간 1회, 기록 경쟁 — 이 기기 안) ③ 장비 융합 사다리 위에 '전설 세트 효과'.

### A4. 첫 1분이 설명 없이 시작한다
- **근거**: 타이틀 화면·튜토리얼 0곳. 재화 말풍선(M15)은 있지만 '무엇을 눌러야 하나'(능력치 구매 → 뽑기 → 장착 → 스킬)는 안내가 없다. 탭 4개·재화 4종·가방·융합·환생이 첫 화면에서 다 보인다.
- **제안**: 첫 판에만 **단계별 손가락 안내** 4~5개(첫 능력치 구매 → 첫 뽑기 → 첫 장착 → 첫 스킬 → 첫 보스), 아직 안 쓰는 탭은 잠금 아이콘(구역 3·5·10 에서 열림). 타이틀 한 장(지시 #153 에서 미룸).

### A5. 벽·골짜기 두 곳이 아직 튄다
- **근거**: 벽 구역 25 = 이웃의 3.54배, 벽 다음 구역 35 = 0.14배(M15-P1 반증). 사람 결정: 지금대로(지시 #168).
- **제안(나중에)**: 시간 제한은 **구역 전체가 아니라 보스 한 마리**에만(실패하면 그 구역 보통 좀비부터 — 후퇴 없음). 이번 실험(`tools/experiments/wall-trial-2026-10-05.patch`)에서 문제였던 '벽에서 계속 죽기'·'처치 수가 같아 쉬움' 을 둘 다 피한다.

## B. 출시 준비

### B1. 광고가 진짜가 아니다
- **근거**: `adReward()` 는 누르면 바로 보상(부품 2배 10분·부활). 광고 SDK 없음, 서버 통신 0(검사 c3 가 막는다).
- **결정 필요**: 출시하려면 광고(AdMob 등)를 앱 껍데기(안드로이드)에서 붙이고 웹뷰와 다리를 놓아야 한다 — c3(서버 통신 금지)·정본과 부딪힌다. 광고 없이 '무료 버튼' 으로 둘지, 붙일지 사람이 정한다.

### B2. 저장 백업이 없다
- **근거**: 저장은 기기 안 localStorage 하나. 앱 데이터 삭제·기기 변경 = 진행 전부 소실.
- **제안**: 설정에 **저장 내보내기/가져오기**(문자열 복사 — 서버 없음, c3 지킴). 안드로이드 자동 백업(`allowBackup`) 확인.

### B3. 설정·마감 손질
- **근거**: 설정 화면 없음. "저장 지우기 (테스트)" 줄이 그대로 노출. 앱 아이콘·이름·버전(0.1.0)이 기본값.
- **제안**: 설정 팝업(소리·진동·저장 내보내기·지우기 두 번 확인) — 테스트 줄은 거기로. 앱 아이콘·타이틀(나노바나나) — 지시 #153 에서 미룬 것.

## C. 기술·운영

### C1. 한 파일 3.7MB 를 손으로 고친다
- **근거**: `game/index.html` 의 약 94% 가 그림 data URI. 편집·diff·충돌이 무겁고(이번 합치기에서 충돌 13곳), 한 줄 고칠 때도 3.7MB 를 다시 쓴다.
- **제안**: **원본은 쪼개고 빌드로 하나로**: `game/src/*.js` + `art/` → `tools/build_game.py` 가 `game/index.html` 을 만든다(결과는 지금처럼 파일 하나 — c6 유지). 거울 해시(c16)는 빌드 결과를 읽으니 그대로.

### C2. 측정이 느리다
- **근거**: 4시드 격자 한 칸 약 9분, 8시드 약 12분. M15 리듬 격자에 약 3시간.
- **제안**: 거울을 '구역 단위 요약 모형'(구역마다 DPS·체력·수입으로 체류를 계산)으로 한 번 더 — 격자는 요약 모형으로 훑고 최종 확인만 거울로.

### C3. 세션이 둘로 갈라졌다
- **근거**: 클라우드 세션 둘이 같은 M15 를 따로 끝냈다(합치기 지시 #169). 원격 세션이 'R007 4항: 정본 수정안은 차단인 채로 커밋, 사람은 git pull 뒤 승인' 을 제안했다(아직 안 받음).
- **제안**: 작업 시작 때 `git fetch` 로 원격이 앞서 있으면 멈추는 검사(c28) · R007 4항을 받을지 사람이 정한다.

### C4. 판정이 쌓여 있다
- **근거**: 미판정 예측 27개(M3~M8 23, M15 4). 판정이 없으면 같은 예측을 다시 세우게 된다.
- **제안**: 사람이 한 번에 몰아 판정할 수 있게 **판정 묶음 문서**(예측 · 근거 기록 · AI 의 맞음/틀림 제안 한 줄씩) — 판정은 여전히 `judge_prediction.py` 로 사람이.

## 제안 순서
1. **A1 소리** — 체감이 가장 크고, 코드만으로(합성음) 된다.
2. **A4 첫 1분 안내 + B3 설정** — 처음 하는 사람이 길을 잃지 않게.
3. **A2 스킬북 쓸 곳 · A3 끝 콘텐츠(하나 골라)** — 회차를 도는 이유.
4. **C1 소스 쪼개기** — 이후 작업이 다 빨라진다(그림 바꿀 때 충돌·용량).
5. **B1 광고 · B2 백업** — 출시를 정할 때.
6. C2·C3·C4 — 운영.
